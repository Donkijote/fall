## Status

Implemented as a standalone, lazy-loaded `/login` route (`/fall/login` with the configured Vite
base path). The existing home page, welcome flow, and gameplay routes are unchanged. This is
a design preview, not an authentication entry point or route guard.

## Atmospheric effects

- Layer gently moving fog around the mountains to create depth.
- Emit subtle fiery embers and ash from the bottom of the screen. Particles rise toward the
  top, drift, disperse, and fade as if generated by an off-screen bonfire.
- Do not show a bonfire or flames. Keep effects behind the content and preserve readability.
- Make decorative layers non-interactive and hidden from assistive technology. Respect
  `prefers-reduced-motion` and keep the effects performant on smaller devices.

## Boundaries

This is presentation-only work: markup, styling, and decorative animation. Do not implement
authentication, sign-up, password recovery, OAuth/provider integration, backend calls,
authentication state, validation flows, or simulated login success. Keep auth actions inert
and prevent accidental submission, reload, or navigation to unimplemented flows. The sole
exception is **Take your seat**, which navigates to the existing main screen without signing
in. Preserve existing application behavior.

## Implementation

The screen lives in `src/modules/login/ui/LoginScreen.tsx`. It uses the existing Card, Input,
Label, Button, and Separator primitives and inherits the app's light/dark theme. The
promotional copy evokes an adventure beyond the mist without fabricated live-player counts.
The suit strip uses four overlapping circular placeholder badges with simple coin, cup,
swords, and club silhouettes from the game icon library. Wingfoot is the temporary emblem
for the login card and Card Hall wordmark. See the [icon credits](../src/assets/login/icons/README.md).
The space-consuming design-preview notice is intentionally omitted on every screen size.
Inputs are editable, but all buttons are non-submitting. **Take your seat** uses React Router to navigate to
`HOME_PATH` (`/fall/` with the configured basename), without checking credentials or creating
authentication state. Recovery, account creation, and provider buttons remain inert. The form
still cancels direct or implicit submission without validation or navigation.

The [login studies](design/main-menu-research/image-concepts/README.md) informed the brass rim,
recessed fields, and warm red primary button. The card keeps its rounded silhouette with
parchment in light mode and charcoal in dark mode. The title sits beside the emblem in compact
landscape and below it elsewhere, without a subtitle or header illustration. Round social buttons use monochrome Google and Apple brand paths from
[Simple Icons](https://github.com/simple-icons/simple-icons/tree/develop/icons), stored locally
in `ProviderIcon.tsx`, alongside local Microsoft window and Facebook brand marks, with
accessible provider labels and native hover titles. No icon-library dependency is added.

`LoginAtmosphere.tsx` uses a local copy of the supplied background at
`src/assets/login/mountain-castle.png`, so rendering does not depend on the external image
host. The supplied image is 512 × 512; larger displays upscale that source.

### Cinematic background

`LoginAtmosphere.tsx` progressively loads `scene/AtmosphereCanvas.tsx` only when WebGL 2 is
available and neither reduced motion nor data saving is requested. Until it is ready, the
original image and CSS vignette remain visible. The enhancement uses the same installed
Three.js, React Three Fiber, and Drei stack as the animation lab; no dependency is added.

The orthographic 2.5D scene composites six passes in explicit order: distant landscape,
far fog, distant embers, valley fog, foreground trees, and near embers. The authored
`src/assets/login/foreground-mask.svg` follows the foreground slopes in the source image's
512 × 512 coordinate system. The foreground shader refines that matte with source luminance,
keeping foliage in front of the fog without treating the castle spires as foreground trees.
All terrain passes share the same cover crop and subtle movement, so no hidden scenery needs
to be invented or inpainted. The image and mask must be retuned together if the artwork changes.

Two shader-driven fog fields use layered, domain-warped noise to continuously evolve while
flowing down the slopes into the castle valley. They are depth-separated transparent planes,
not raymarched volumetric fog or a fully modeled castle. Pointer-driven movement is smoothed
and gives the atmosphere more parallax than the terrain; coarse-pointer devices disable it.
GPU particles rise at two depths, with deterministic initial phases, lateral dispersion,
varying apparent sizes, and fading ember/ash colors. Warm grading and edge darkening apply to
the terrain and fog while embers retain their glow.

Fog and embers advance continuously from elapsed frame time, independently of mouse input.
Parallax is an additional pointer effect, not the animation driver. `animateMaterials.ts`
updates the attached ShaderMaterial uniforms directly: the installed R3F version copies
scalar uniform wrappers when applying props, so mutating the original `uTime` prop leaves
the rendered shader frozen even though shared pointer vectors still move. Regression tests
use R3F's actual `applyProps` to cover that binding behavior and stationary-pointer animation.

Desktop quality is capped at DPR 1.5 and 160 particles; compact/coarse-pointer devices use
DPR 1 and 80 particles. The R3F render loop pauses while the document is hidden, and time
steps are clamped on resume. Component unmount cleans up pointer, media, visibility, and
context-loss subscriptions; R3F owns the geometry/material and renderer lifecycle.

Reduced motion, data saving, missing WebGL, renderer initialization failures, shader errors,
and context loss retain the static backdrop without blocking the login form. Preference
changes are observed live. The canvas and all decorative layers are hidden from assistive
technology and cannot intercept clicks or keyboard focus.

### Interface motion

GSAP animates the introductory copy and login card entrance. A single warm
highlight sweeps around the brass rim, fades out, and pauses before repeating.
`LoginScreen.css` defines the static gradient and mask that keep the highlight
on the rim. GSAP drives its angle and opacity independently of form focus.
The scoped timelines are reverted on unmount and when reduced motion is enabled.

The WebGL layer also uses GSAP for its reveal after the first rendered frame.
Three.js and React Three Fiber own the scene motion. Tailwind and CSS define
the static layout and appearance. The login controls override the transitions
and press movement inherited from the generated primitives. Reduced motion
retains the static brass frame and the original backdrop.

## Verification

### Responsive layout

Tailwind handles responsive layout, the static atmosphere layers, and forced-color
text fallbacks.

- Phone portrait: show a compact eyebrow/headline above the centered card, pushing the form
  down slightly. Short portrait screens scroll vertically.
- Compact landscape below `xl`: keep the introduction on the left and give the card three
  quarters of the available row width. Inside the card, stack email/password and the primary
  action in the left column; place a two-by-two grid of round Google/Apple/Microsoft/Facebook
  buttons and account creation in a separate, softly surfaced right column. Keep the emblem
  beside the card title and hide the decorative suit row. Card padding, field gaps,
  and control sizes grow with available viewport height using clamped Tailwind utilities,
  giving taller landscape phones more breathing room. Remove the internal scroll container and height
  cap. An intrinsic auto-fit content grid stacks these sections only if each cannot retain
  13rem of width. Below `sm`, hide the outer introduction to prioritize the form.
- Tablet portrait from `sm`: stack a compact headline above the card; hide the longer prose
  and suit placeholders until `lg`.
- Wide landscape/desktop from `xl`: keep the original promotional column and vertical login
  card. Portrait tablet layouts remain unchanged, with larger type/spacing at `xl` and `2xl`.
- Inputs and primary/social buttons retain at least 44px height. Mobile inputs use 16px type.
  Keep vertical scrolling available for the on-screen keyboard, enlarged text, and short
  windows; never clip the form or require horizontal scrolling.

Browser screenshots are captured from the production build at representative CSS viewport
sizes, not from physical devices. Verify both orientations when changing the layout. The
WebGL cover crop and foreground matte remain aligned as the viewport resizes.

The initial production browser pass covered 390 × 844, 844 × 390, 820 × 1180, 1180 × 820,
1440 × 900, 320 × 568, 568 × 320, and 1280 × 720. The two-column landscape refinement
specifically covers the reported 852 × 393 and 1040 × 480 layouts: both fit without page
or card scrolling, retain 44px controls and 16px input text, and remove the preview notice.
The corresponding 393 × 852 and 480 × 1040 portrait compositions retain the headline above
the card. Very small portrait and keyboard-sized viewports retain safe vertical scrolling
rather than shrinking touch targets.

### Automated and visual checks

Component tests cover labeled inputs, keyboard focus and typing, inert actions, prevented
submission, main-screen navigation by mouse and keyboard with empty/invalid credentials,
no network/storage writes, and decorative-layer isolation. Atmosphere tests mock the renderer
to cover progressive loading, live preferences, reduced-motion/data-saving/no-WebGL paths,
quality selection, visibility pausing, failure containment, and subscription cleanup. Pure
tests verify image-cover alignment, deterministic particle seeds, and quality budgets. Router
tests cover the login route in development and production with the `/fall` basename.

Run `pnpm check`, `pnpm build`, and `pnpm test:coverage`. The production browser pass also
confirms the WebGL backdrop initializes and renders across the screenshot sizes; no new
production shader errors were observed. Physical-device verification is still needed for
GPU compatibility/frame rate, actual keyboard and safe-area behavior, foreground matte edges,
fog appearance, pointer parallax, light/dark contrast, context loss, and system reduced motion.
The automated unit tests do not render WebGL pixels. The WebGL runtime is a separate lazy
production chunk; the build currently warns about large JavaScript chunks, including this
graphics runtime.
