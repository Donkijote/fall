# Login screen

Tracking issue: [#92](https://github.com/Donkijote/fall/issues/92).

## Status

Planned only. This branch establishes the scope and draft PR; it does not implement the screen
or change application behavior. Keep the tracking issue in the Fall project's Ready column
until implementation starts.

## Layout and components

Use the requester-provided screenshot as the composition reference: a full-screen mountain
and castle scene, a promotional section on the left, and a login card on the right. Stack the
layout appropriately on smaller screens. Use Fall's branding rather than unrelated game copy
or fabricated live-player counts from the reference.

Compose the card with the project's existing shadcn/ui primitives: labeled email and password
fields, a primary login button, password-recovery affordance, social sign-in buttons, a
separator, and an account-creation affordance. Follow the existing semantic theme tokens,
Spline Sans/Cinzel typography, and Lucide icons described in `docs/shadcn-migration.md`.

## Atmospheric effects

- Layer gently moving fog around the mountains to create depth.
- Emit subtle fiery embers and ash from the bottom of the screen. Particles rise toward the
  top, drift, disperse, and fade as if generated by an off-screen bonfire.
- Do not show a bonfire or flames. Keep effects behind the content and preserve readability.
- Make decorative layers non-interactive and hidden from assistive technology. Respect
  `prefers-reduced-motion` and keep the effects performant on smaller devices.

## Boundaries

This is presentation-only work: markup, styling, and decorative animation. Do not implement
authentication, sign-up, password recovery, OAuth/provider integration, backend calls,
authentication state, validation flows, or simulated login success. Keep auth actions inert
and prevent accidental submission, reload, or navigation to unimplemented flows. Preserve
existing application behavior.

When implementation is complete, verify responsive layouts, accessible labeling and keyboard
access, contrast, reduced motion, and inert auth controls. Run the relevant tests plus
`pnpm check`, `pnpm build`, and `pnpm test:coverage`.
